# sogaffer
SoGaffer (Sorare Optimal Gameweek Alignment Formation For Effective Results) is a complementary tool to build optimal lineups on Sorare.

This repository contains the implementation of the Final Degree Project `Sistema de gestión y estrategia para la selección de
jugadores y alineaciones en Sorare`, required to obtain the Bachelor’s Degree in Computer Engineering at the University
of Cantabria. Therefore, it is highly likely **this repository will not be maintained after its defense**.

## Definition of Done (DoD)

The development of a user story, or any other item of the Product Backlog, will be considered complete when it fulfills
the following Definition Of Done:

1. An implementation has been created for the Product Backlog item.
2. A test plan has been defined for the elements included in the Product Backlog item.
3. The created implementation successfully passes all unit tests defined in the test plan of the Product Backlog item.
4. The created implementation successfully passes all integration tests defined in the test plan of the Product Backlog
   item.
5. The created implementation successfully passes all end-to-end (E2E) tests defined in the test plan of the Product
   Backlog item.
6. The created implementation successfully passes all user interface tests defined in the test plan of the Product
   Backlog item.
7. The created implementation successfully passes all acceptance tests defined in the test plan of the Product Backlog
   item.
8. If the implementation of the Product Backlog item has required any changes to the classes that define the domain
   model of the application, the changes are reflected in the associated UML model.
9. If the implementation of the Product Backlog item has required any architectural changes, these changes are reflected
   in the associated UML model.
10. The Product Backlog item branch has been merged into the `develop` branch.
11. After merging the user story into the `develop` branch, it has been verified that the full product still passes all
    previously defined tests.
12. Once integrated into the rest of the product, it has been verified that the created implementation satisfies the
    quality criteria.
13. The corresponding quality reports have been generated. At least one quality report must be generated in each sprint.
14. The user manual of the application has been updated so that it reflects the newly-implemented Product Backlog item.
15. A file with `.jar` extension has been generated and contains the latest version of the product plus the
    newly-implemented Product Backlog item.
16. The new version of the product is merged into the `main` branch and properly tagged.
